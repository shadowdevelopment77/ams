## A real bug hit and fixed

`npx shadcn@latest init` did not correctly resolve the `@/*` alias when writing generated files — it created a **literal directory named `@`** at the frontend project root (`./@/components/ui/button.tsx`, `./@/lib/utils.ts`) instead of writing into `src/components/ui/` and `src/lib/`. Fixed by moving both files to their correct locations and deleting the stray `@` folder. Worth checking again if a future `npx shadcn add <component>` call is run — same failure mode could recur.

## Verification performed

- `npx tsc -b` → 0 errors (after removing the deprecated `baseUrl` option).
- `npm run build` → clean production build (228.96 kB JS / 72.48 kB gzipped, 23.78 kB CSS / 5.03 kB gzipped).
- `npm run dev` → booted on `:5173`; confirmed via `curl` that both the HTML shell and `/src/main.tsx` served without transform errors, and checked the dev server log directly for silent failures.
- `npm run lint` → 1 warning, from shadcn's own generated `button.tsx` (`react/only-export-components` — it exports both the `Button` component and a `buttonVariants` constant from the same file, which is shadcn's standard convention everywhere, not a real issue).
- `git add -n frontend/` dry-run confirmed exactly 17 real source files would be staged — `node_modules`, `dist`, and `.env.local` all correctly excluded by the scaffold's own `.gitignore`.
